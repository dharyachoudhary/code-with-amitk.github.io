What is enum

Enums are User defined data type(Similar to other languages) which can be assigned some limited values. In rust enum variable can/cannot hold the data (Eg: String).
C++ enums are named integer constants, whereas Rust enums are Data Types that can carry distinct payloads of data per variant

Properties of enum in Rust

Property Description
Individual variants can contain completely different types of data 

// Rust
enum WebEvent {
    PageLoad,                 // No data
    KeyPress(char),           // Tuple variant
    Click { x: i64, y: i64 }, // Anonymous struct variant
}
Attach behavior directly to your enums using impl blocks 

impl WebEvent {
    fn log_event(&self) {
        // Method logic here
    }
}
Safety via Exhaustive Pattern Matching Rust forces you to account for every single enum variant using the match keyword. Leaving out a variant causes a compile-time failure, preventing unintended runtime edge cases.
wrt C++. While a modern C++ compiler can generate warnings for unhandled cases inside a switch statement on an enum class, it will still compile and run.
Specialized optimizations Because the Rust compiler understands the exact layout of its enums, it performs specialized optimizations.

enum types

1. Not holding data


#[derive(Debug)]            //To print debugging information
enum Color{                 //Declare enum
    Red,
    Blue,
    Green
}

fn fun (a:Color) {          //Print enum after passing to function
    println!("{:#?}",a);
}

fn main() {
    let a:Color = Color::Red; //Initialize variable with enum value
    fun(a);
}

2. Enum Holding the data


// Enum holding 1 datatype
use std::{string::String, u32};

#[derive(Debug)]
enum Address{                     //1. Enum variable storing string data
    IPv4(String),
    IPv6(String),
}

fn fun (addr:&Address) {          //3. Passing enum variable to function and print
    println!("{:#?}",addr);
}

fn main() {
    let router1:Address = 
      Address::IPv4(String::from("192.168.1.1"));   //2. Creating enum variable having string data(192.168.1.1)
    fun(&router1);
}

Option <T>

Option<T> is a built-in enum used to represent a value that may or may not be present.
Because Rust does not have null values like many other programming languages, it relies on Option<T> to safely handle the potential absence of data at compile time, eliminating the risk of null-pointer exceptions.

It can have 2 values
  Some(T): Encloses a valid value of type T.
  None: Represents the absence of a value 

pub enum Option<T> {
    Some(T), // Contains a value of type T
    None,    // Represents the absence of a value
}

How to get inner value of Option

Pattern Matching (match) Most robust way if let (Handling Only one case) unwrap_or unwrap() {AVOIDED} ? Operator (Early Return) 
let some_score: Option <i32> = Some(95);
match some_score {
    Some(score) => println!("score: {}", score),
    None => println!("No score recorded"),
}
 
let item: Option <String> = 
              Some(String::from("Sword"));

if let Some(weapon) = item {
    println!("Equipped: {}", weapon);
}
// None is not handled
 
let a: Option <i32> = None;
let b = a.unwrap_or(2); // Falls back to 2
 

// We can violently pull the value out using 
// .unwrap() or .expect().
// However, if the variant is None,program crash
let value = Some("Safe").unwrap(); // Works fine


// If you are inside a function that returns an Option, 
// you can append the ? operator to an Option value. 
// If the value is Some, it extracts the inner data 
// and continues; if it is None, it immediately 
// returns None from the entire function.
fn fun() -> Option <String> {
    let t = test()?; // Returns early if None
    ...
}

Creating NULL was mistake?

Tony Hoare(inventor of NULL) said invention of NULL is his Billion dollar mistake. Why?
Using NULL value as non-NULL value. Eg: derefercing NULL ptr. It will crash. Problem is not in NULL but at places it gets misused.
There are multiple situations, where crash is caused due to NULL. Example: NULL References when derefrenced will cause crash 


int fun(struct A*& p){              //Funtion taking NULL reference
    if (p == nullptr)
        cout << "Got Null ptr reference\n";
    cout << p->a;
}
int main(){
    struct A* p = nullptr;
    fun(p);
}
$ ./a.out
Got Null ptr reference
Segmentation Fault

How Rust avoid Null ptr?

1. Variable that can have NULL/other value is declared as Option <T>
2. Rust does not allow creating structure object without initializing its members. It can be initialized with Some or None. No crash, None will be printed.
